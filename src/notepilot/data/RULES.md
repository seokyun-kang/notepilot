# 노트 에이전트 규약

이 폴더는 notepilot으로 관리하는 노트 보관함이다. 목표는 **가독성·정확성·깔끔함**이다. 사용자의 현재 명시적 요청이 이 파일보다 우선하며, 이미 승인된 작업을 다시 승인받지 않는다.

이 파일이 있는 `.notepilot/` 폴더는 도구의 것이며 `notepilot upgrade`가 통째로 교체한다. 여기 있는 파일은 고치지 않는다. 이 보관함만의 지침은 보관함 루트의 `AGENTS.md`에 있고, 이 파일과 다르면 `AGENTS.md`가 우선한다.

## 시작

1. 이 파일을 끝까지 읽는다.
2. 보관함 루트의 `AGENTS.md`에서 이 보관함의 용도·분류·명명·결정을 확인한다. 절 제목과 속성은 아래에 적힌 대로 고정이다. 폴더 이름은 아래가 기본값이며, `notepilot.json`에 `folders`가 있으면 거기 적힌 이름이 실제 폴더다.
3. 루트의 `README.md`와 해당 분야의 index, 관련 기존 노트를 읽고 제목·본문·별칭으로 중복을 찾는다.
4. 새 노트는 `notepilot new <분야> <제목> [--type comparison|lab|…]`로 만든다. `templates/`의 양식에 제목과 오늘 날짜를 채운 파일이 생기며, 그 안의 안내 주석을 따라 작성한 뒤 주석을 지운다.
5. `notepilot sync`로 갱신하고 `notepilot check`로 검사한 뒤 변경 내용을 직접 검토한다.

세부 규칙은 해당 작업을 할 때 읽는다.

| 명령 | 내용 | 읽는 때 |
| --- | --- | --- |
| `notepilot guide writing` | 자료 참조 범위, 근거 기준, 설명과 개념 분리 | 내용을 쓰거나 고칠 때 |
| `notepilot guide format` | 속성, 공통 형식, 링크·Callout·목차 호환성 | 새 노트, 형식 오류 |
| `notepilot guide workflow` | 생성·이동·통합·보관·삭제, inbox 편입, 점검, 완료 조건 | 파일을 옮기거나 지울 때, 점검 요청 |

`notepilot` 명령을 실행할 수 없으면 그 사실을 사용자에게 알린다. 실행하지 않은 검사를 통과했다고 보고하지 않는다.

## 폴더

| 위치 | 역할 |
| --- | --- |
| `notes/<분야>/` | 정식 노트. 분야는 `notes/` 바로 아래 폴더 |
| `inbox/` | 정리 대기 메모. 자유 형식, git 추적 |
| `temp/` | 사용자의 임시 작업 공간. git 미추적. 요청 없이는 읽지 않음 |
| `templates/` | 노트 양식 |
| `assets/` | 첨부 |
| `.notepilot/` | 도구가 관리하는 공통 규약·양식 원본. 고치지 않음 |

이 문서와 `notepilot guide`는 기본 이름으로 설명한다. `notepilot.json`의 `folders`에 다른 이름이 있으면 그 이름으로 바꿔 읽는다. 폴더 이름을 바꿀 때는 직접 옮기지 말고 `notepilot rename <폴더> <새 이름>`을 쓴다. 사용자가 더한 다른 폴더의 역할은 `AGENTS.md`에서 확인한다.

## 정식 노트의 형식

파일명(확장자 제외)이 제목이고 본문의 단일 H1과 같아야 한다. 속성은 다음 일곱 개와 선택 속성 aliases만 쓴다.

| 속성 | 값 |
| --- | --- |
| type | concept / comparison / lab / reference / index / report |
| tags | 문자열 목록 |
| status | draft / active / archived |
| created, updated | YYYY-MM-DD. created는 보존, updated는 의미 있는 본문 수정 때만 갱신 |
| related | 관련 정식 노트의 보관함 기준 경로 목록 |
| verification | unverified / source-checked / reproduced / needs-review |

구조는 **속성 → H1 → `> [!NOTE]` 요약 → (본문 H2가 둘 이상이면 목차) → 본문 → 근거와 참고 자료 → 관련 문서** 순서다.

- 링크와 이미지는 상대 경로의 일반 Markdown 링크로 쓰고 공백·괄호는 URL 인코딩한다. 위키 링크(`[[ ]]`)는 쓰지 않는다. Obsidian과 GitHub 양쪽에서 읽히게 한다.
- `toc`·`related`·`summary` 관리 주석 사이는 도구가 채운다. 손으로 쓰지 않으며 주석을 지우지 않는다.
- 관련 문서는 `related` 속성에 적는다. 목록은 `notepilot sync`가 만든다.
- 템플릿의 안내 주석과 자리표시자는 완성 노트에 남기지 않는다.

## 내용 원칙

- 한 문서는 개념 하나 또는 명확한 목적 하나를 다룬다. 같은 개념의 노트가 있으면 새로 만들지 않고 보완한다.
- 처음 읽는 사람이 이 문서와 연결된 선행 노트만으로 무엇인지·왜 필요한지·어떻게 동작하는지 이해할 수 있게 쓴다. 용어 나열이나 외부 링크로 설명을 대신하지 않는다.
- 개념·기술 노트의 핵심 설명은 공식 문서·명세·해당 버전의 소스·원저 논문 등 일차 자료와 실제로 대조한다. 대조하지 못했으면 unverified로 두고 한계를 근거 절에 적는다.
- 출처·관찰·실행 로그·테스트 통과를 만들어 내지 않는다. 실행하지 않은 결과는 예상 결과로 적는다.
- 사용자가 적은 맥락·조건·실제 관찰은 보존한다. 기존 내용의 오류를 고칠 때는 **기존 표현 → 수정안·변경 이유·근거**를 먼저 제시하고 승인된 범위에서 고친다.
- 내용의 근거로 읽는 자료는 이 보관함 안의 파일, 사용자가 대화로 준 자료, 인증 없이 접근 가능한 공개 웹 자료로 한정한다. 보관함 밖의 로컬 파일이나 계정 기반 앱의 원본을 찾아 읽지 않는다.

## 비밀 값

API 키·토큰·비밀번호를 `notes/`·`inbox/`·`assets/` 등 추적되는 위치에 쓰지 않는다. 사용자가 붙여넣은 내용에 비밀 값이 보이면 옮겨 적지 말고 알린다. `notepilot check`의 패턴 검사는 일부만 잡으므로 통과를 안전 보증으로 보지 않는다.

## 수정 순서와 보고

수정 순서는 **노트 → 분야 index → `notepilot sync` → `notepilot check` → 보고**다. 모든 정식 노트는 README.md에서 링크를 따라 도달할 수 있어야 한다. 일반 노트 작업에서 `AGENTS.md`·템플릿·`notepilot.json`을 고치지 않는다. 사용자가 보관함 지침 변경을 요청했을 때만 `AGENTS.md`를 고친다.

도구 통과는 형식과 링크가 맞다는 뜻이며 사실 검증·예제 실행·화면 확인을 뜻하지 않는다. 최종 보고에는 변경한 문서, 핵심 보정, 실제로 한 검증, 남은 제한을 간단히 적는다.
