# 형식 안내

정식 노트(`notes/` 아래, `excluded_note_paths` 제외)에 적용하는 형식이다. `inbox/`와 `temp/`는 자유 형식이다. 두 공통 절의 제목(`근거와 참고 자료`, `관련 문서`)과 `목차`는 고정이며 바꾸면 검사에서 오류가 난다.

## 속성

제목은 속성으로 두지 않는다. **파일명(확장자 제외)이 제목이며 본문의 단일 H1과 같아야 한다.** 분야도 속성이 아니라 `notes/` 바로 아래 폴더로 정한다.

| 속성 | 의미 |
| --- | --- |
| type | concept / comparison / lab / reference / index / report |
| tags | 분류·검색을 위한 문자열 목록. 형식은 `tag_pattern` |
| status | draft / active / archived. 문서의 작성·사용 상태이며 복습 상태가 아님 |
| created | 실제 최초 작성일. YYYY-MM-DD |
| updated | 의미 있는 본문 수정일. YYYY-MM-DD |
| related | 실제 존재하는 관련 정식 노트의 보관함 기준 경로 목록 |
| verification | unverified / source-checked / reproduced / needs-review |

aliases는 선택 문자열 목록이며 이전 제목·검색에 필요한 별칭을 보존한다. 속성과 값의 종류를 임의로 늘리지 않는다. 출처·환경·검증 세부 사항은 본문에 적는다.

- 평면 문자열·날짜·문자열 목록만 사용한다. 문자열은 큰따옴표, 목록은 `[]` 또는 YAML 블록 목록으로 쓴다. 중첩 객체·여러 줄 값·YAML 앵커·사용자 정의 태그는 쓰지 않는다.
- 새 지식은 concept·draft·unverified에서 시작한다. 내용과 속성을 채워 사용할 수 있으면 active로 전환한다.
- created는 보존하고 updated는 의미 있는 본문 수정 때만 갱신한다. 이동·형식·목차·관련 링크 생성만으로 날짜를 바꾸지 않는다. 날짜는 작성하는 기기의 현지 날짜를 쓴다. 변경 이력은 git 기록이 담당하며 본문에 별도 이력 표를 두지 않는다.
- 기존 날짜가 불명확하면 임의로 만들거나 파일 시각으로 추측하지 않는다. 사용자가 보정 기준을 승인한 경우만 보정하고 루트 AGENTS.md에 한 번 적는다.
- 파일명에는 경로 구분자와 `#`, `|`, `^`, `:`, `%%`, `[[`, `]]`, 운영체제 예약 문자를 쓰지 않는다. 이름을 바꾸면 이전 제목을 aliases에 남긴다.

### verification의 뜻

- unverified는 충분히 대조하지 않은 상태다. 문서가 깔끔하거나 링크가 있다는 이유로 올리지 않는다.
- source-checked는 공식 문서·명세·해당 소스·원저 논문 등 주제에 적합한 일차 자료와 실제 대조했고 본문에 근거·적용 범위를 적은 상태다. 보충 자료의 링크만 추가한 것으로 부여하지 않는다. 근거 절에 확인한 자료의 링크가 있어야 한다.
- reproduced는 핵심 동작을 실제 실행했고 환경·절차·관찰 결과를 기록한 상태다. 모든 주장에 대한 보증은 아니다.
- needs-review는 충돌·모호함·버전 문제 등의 재확인 이유를 본문에 적은 상태다.
- active와 unverified는 함께 쓸 수 있다. status와 verification을 혼동하지 않으며 속성과 본문을 일치시킨다.

## 공통 형식

| 순서 | 요소와 조건 |
| --- | --- |
| 처음 | Frontmatter → 파일명과 같은 단일 H1 → 내용이 있는 NOTE 요약. H1 바로 다음의 첫 본문은 `> [!NOTE]` Callout |
| 탐색 | 아래 두 공통 절을 뺀 본문 H2가 둘 이상이면 `목차` 절과 toc 관리 영역 필수. 더 짧으면 생략 가능 |
| 본문 | 목적에 맞는 설명·예제·표·도식. 소제목·개수·분량은 자유 |
| 끝 1 | `근거와 참고 자료`. 확인한 것, 미확인·미실행 범위, 적용 버전·조건을 적고 사용한 출처를 연결. verification과 일치시킴. 출처가 없으면 그 사실을 적고 만들어 넣지 않음 |
| 끝 2 | `관련 문서`. related 관리 영역 한 쌍은 항상 유지. 관계가 없으면 속성은 `[]`, 영역은 비움 |

- 도입 NOTE는 모든 정식 노트의 공통 요소다. 요약에 고정 문구나 장식용 제목을 반복하지 않는다.
- `related` 속성이 관련 문서 목록의 원본이다. 본문에서 설명상 밀접하게 연결한 노트를 선별해 속성에 적으면 `notepilot sync`가 목록을 만든다. index의 전체 탐색 목록과 reference의 자료 목록을 related에 전부 복사하지 않는다. 관계 설명은 관리 영역 밖에 쓴다.
- 전용 템플릿이 없는 type은 기본 `note.md`의 공통 형식을 쓰되 본문을 실제 목적에 맞춘다. index·reference에 개념·실습 절을 억지로 채우지 않는다.
- 템플릿의 안내 주석과 자리표시자는 완성 노트에 남기지 않는다. toc·related 관리 주석은 보존한다.

## 호환성

- **Obsidian·GitHub 동시 호환을 최우선**으로 선택한다. 공통 방식으로 충족할 수 없는 기능만 **Obsidian 우선**으로 적용하고 GitHub의 대체 경로나 제한을 밝힌다.
- 본문과 이미지는 상대 경로의 일반 Markdown 링크를 사용한다. 공백·괄호 등은 URL 인코딩하고 존재하는 파일·절만 연결한다. 이동·삭제 때 들어오는 참조도 갱신한다.
- Callout은 NOTE·TIP·IMPORTANT·WARNING·CAUTION만 사용한다. 첫 줄은 `> [!NOTE]`처럼 단독으로 적고 전용 접기·사용자 제목을 넣지 않는다. 필수 도입 요약 외의 Callout은 중요한 내용에만 사용한다.
- Mermaid는 흐름·관계 설명에 실제 도움이 될 때만 추가한다. 기본 문법 위주로 작성하고 본문 설명도 남긴다. 빈 도식·장식용 반복 도식은 만들지 않는다.
- 목차·절 링크의 대상 제목에는 Obsidian에서 문제가 될 수 있는 `#`, `|`, `^`, `:`, `%%`, `[[`, `]]`를 사용하지 않는다. 대상 제목이 해당 문서에서 중복되지 않도록 구별한다. 문제가 있는 제목은 의미를 유지한 안전한 표현으로 고치고, 들어오는 링크와 생성 목차를 함께 갱신한다. 링크 주소에서만 기호를 제거하거나 추측한 앵커를 만들지 않는다. 안전한 제목은 단순한 한 단어이면 공통 소문자 앵커를, 그 밖에는 실제 제목의 URL 인코딩을 사용한다. 공백·한글·괄호를 임의로 제거하지 않는다. GitHub 자동 앵커와 다르면 GitHub 기본 문서 목차로 보완한다.
- H2/H3로 목차를 구성하고 목차 자체·코드 블록 안의 제목은 제외한다. 같은 절 제목이 반복되면 문맥이 구별되는 제목으로 고친다. 파일 이동·제목 변경 후에는 링크의 실제 파일·절 존재와 들어오는 참조를 검사한다. 정적 검사와 앱에서의 이동 성공은 구분하며 대표 링크는 실제 클릭한다. 앱 접근이 불가능하면 미확인 범위를 보고하고 이동 성공으로 표시하지 않는다.
- toc·related·summary 관리 영역 안에는 수동 설명을 쓰지 않는다. related에는 자기 자신·중복·외부 URL을 넣지 않는다. 수동 관련 설명은 영역 밖에 적는다.
- Bases는 Obsidian 전용 조회임을 명시한다. GitHub에서는 일반 탐색 링크와 홈 문서의 정적 현황 표로 보완한다. 실시간 조회와 정적 자료를 같은 것으로 설명하지 않는다.
- 저장 시 자동 실행이 구성되지 않았다면 자동 갱신된다고 말하지 않는다. 노트 작업 완료 전에 `notepilot sync`와 `notepilot check`를 실행한다. 앱의 속성 반영과 도구의 정적 영역 생성을 구분한다.
- 첨부를 삭제하기 전에 사용 여부를 확인한다. 출처·고유 내용·첨부를 보존하고 파일 이름 변경 시 이전 제목과 별칭도 검토한다.
