# 노트 작성·정리

호출에 함께 적은 주제·본문·자료와 사용자의 제약을 작업 입력으로 쓴다. 규칙을 이 스킬에 복제하지 않는다. 공통 규약은 보관함의 `.notepilot/RULES.md`, 보관함별 지침은 루트 AGENTS.md, 세부 규칙은 `notepilot guide <주제>`가 원본이다.

## 시작

1. 보관함을 정한다. 사용자가 지정한 경로가 우선이고, 없으면 현재 위치에서 상위로 `notepilot.json`이 있는 폴더를 찾는다. 찾지 못하면 다른 폴더로 대체하지 말고 경로를 묻는다.
2. 보관함의 `.notepilot/RULES.md` → 루트 AGENTS.md → README.md와 분야 index → 관련 기존 노트 순서로 읽는다.
3. 작업에 맞는 안내를 읽는다: 내용은 `notepilot guide writing`, 형식은 `notepilot guide format`, 이동·삭제·inbox 편입·점검은 `notepilot guide workflow`.

다른 프로젝트에서 호출됐다면 보관함 기준으로 경로를 해석하고, 현재 프로젝트의 파일을 노트로 착각해 편집하지 않는다.

요청 대상이 AGENTS.md가 지정한 별도 작업 공간(정식 노트 폴더 밖에 사용자가 만든 폴더)이면 그 공간의 규칙과 도구를 따른다. 그 공간의 문서에 정식 노트의 속성·절·양식을 강제하지 않고, 정식 노트와 검사·집계를 섞지 않는다.

## 요청 종류별 진행

| 요청 | 진행 |
| --- | --- |
| 주제만 있음 | 이해에 필요한 기본 개념부터 정리한다. 넓은 주제는 독립적인 학습 목적 단위로 나누되 교과서 전체나 학습 계획으로 넓히지 않는다 |
| 본문·자료가 있음 | 의미와 근거를 보존하며 분류·구조·모호한 설명을 정리한다. 원문에 없던 관찰·실행 결과를 만들지 않는다 |
| 기존 노트 보완 | 해당 문서 전체를 먼저 읽고 부족한 부분만 고친다. 불필요한 새 파일을 만들지 않는다 |
| inbox 정리 | workflow 안내의 편입 순서를 따른다. 원문 메모는 승인 없이 지우지 않는다 |
| 점검 | `notepilot report`의 후보를 출발점으로 노트를 직접 읽고 모순·낡은 주장·빠진 개념과 교차 참조를 찾아 보고한다 |

일반 호출은 노트 작성까지 진행한다. 사용자가 변경안만 요청했거나 승인 단계를 지정했으면 그 범위에서 멈춘다. 입력이 없거나 핵심 목적을 정할 수 없을 때만 짧게 확인한다.

## 작성

- 제목·본문·별칭으로 중복을 찾는다. 같은 개념은 기존 노트를 보완하고, 독립적으로 다시 쓰일 설명일 때만 분리한다.
- 새 노트는 `notepilot new <분야> <제목> [--type …]`로 만들고 생긴 파일을 채운다.
- 핵심 설명은 일차 자료와 실제로 대조한다. 확인하지 못한 범위는 verification과 근거 절에 그대로 적는다.
- 기존 내용의 오류는 기존 표현 → 수정안·변경 이유·근거를 먼저 제시하고 승인된 범위에서 고친다.
- 사용자가 준 내용에 API 키·토큰 같은 비밀 값이 있으면 노트에 옮기지 말고 알린다.

## 완료

1. 가장 가까운 분야 index나 README.md에서 노트에 도달할 수 있게 연결한다.
2. `notepilot sync`를 실행하고 `notepilot check`가 통과할 때까지 오류를 고친다. 명령을 실행할 수 없으면 그 사실을 보고한다.
3. 만들거나 고친 문서, 분리·배치와 핵심 보정의 이유, 실제로 한 근거 확인과 검사, 남은 제한을 간단히 보고한다. 형식 검사 통과를 사실 검증으로 표현하지 않는다.
