# 내용 작성 안내

정식 노트의 내용을 쓰거나 고칠 때의 기준이다. 형식은 `notepilot guide format`, 파일 작업 절차는 `notepilot guide workflow`에서 다룬다.

## 자료 참조 범위

- 내용의 근거로 읽을 수 있는 자료는 대상 노트 보관함 안의 파일, 사용자가 대화로 제공한 본문·첨부, 인증 없이 접근 가능한 공개 웹 자료다. 공식 홈페이지·공식 문서·공개 소스 저장소 등을 우선한다. URL이 있다는 이유만으로 공개 자료로 간주하지 않는다.
- 보관함 밖의 로컬 파일·다른 저장소·상위 디렉터리·개인 앱 데이터는 읽거나 검색·추적하지 않는다. 보관함 안의 심볼릭 링크나 상대 경로가 밖을 가리켜도 따라가지 않는다. 로그인이 필요한 앱·클라우드 서비스·커넥터의 원본과 비공개 저장소 자료를 근거 수집 목적으로 열지 않는다. 로그인된 브라우저·앱 화면으로 우회 확인하지 않는다.
- 과거 앱·서비스 원본 링크와 당시 확인 기록은 출처 이력으로 보존할 수 있지만 재열람 지시나 현재 검증 근거로 해석하지 않는다. 필요한 내용이 없으면 미확인으로 남기고, 사용자에게 저장소 안에 자료를 넣거나 대화로 제공하도록 요청한다. 외부 경로를 추측해 찾아보거나 접근 승인을 반복 요청하지 않는다.
- 이 범위는 학습 내용·원문 수집에 적용한다. 보관함 선택에 필요한 스킬 지침·기본 경로 설정과 실행 도구의 필수 환경 메타데이터는 최소한으로 읽을 수 있지만 노트 내용의 근거로 쓰지 않는다. 다른 보관함은 사용자가 대상으로 명시한 경우에만 그 루트를 기준으로 판단한다.

## 노트의 품질

노트는 특정 실습 저장소와 함께 있어야 읽히는 구조로 만들지 않는다. 설명에 필요한 코드·타입·설정·입력/예상 결과는 본문이나 실제 선행 노트에 담고, 완전 실행 예제와 설명용 생략 예제를 구분한다. 외부 실습 프로젝트 경로·파일을 찾아보라는 안내로 설명을 대신하지 않는다. 적용 버전·환경 조건은 필요한 해당 노트에만 기록한다. PDF·사진·참고 링크는 근거·첨부로 유지할 수 있지만 홈 문서에 자료별 버전표나 실습 프로젝트 관리 목록을 자동 추가하지 않는다.

### 사용자 맥락과 지식의 근거

- 수업 메모·문제 풀이·실습 기록은 사용자가 작성한 목적·상황·조건·실제 관찰을 보존한다. 그 안에서 일반 개념이나 기술 동작을 설명하는 부분에는 아래 근거 기준을 적용한다. 기록의 맥락을 보존한다는 이유로 틀리거나 부정확한 설명을 그대로 유지하지 않는다.
- 기존 내용의 오류·부정확한 표현을 수정할 때는 수정 전에 **기존 표현 → 수정안·변경 이유·근거**를 변경안에 제시하고 승인된 범위에서 설명 자체를 고친다. 이미 구체적인 수정안이 승인됐다면 중복 승인을 요구하지 않는다. 실제 관찰과 공식 설명이 다르면 조건·시점·버전과 차이를 설명하며, 관찰·로그·교수자의 실제 지시를 예상 결과나 새 지시로 덮어쓰지 않는다. 근거가 부족하면 확정적으로 고치지 않고 확인할 사항으로 남긴다.
- 개념·기술 노트의 정의·동작 원리·사용 계약·적용 조건 등 핵심 설명은 공식 문서·명세·해당 버전의 소스·원저 논문 등 주제에 적합한 일차 자료를 실제로 확인해 작성한다. 불확실해 보이는 주장만 확인하는 방식으로 한정하지 않는다. 적용 버전·조건을 확인하고 최신 설명을 이전 환경의 보장으로 옮기지 않는다.
- 교재·논문·전문 해설은 저자·발행 주체·근거·적용 시점과 버전을 확인해 보충 자료로 사용한다. 검색 순위나 여러 글의 반복만으로 검증됐다고 판단하지 않는다. 일차 자료가 없거나 접근할 수 없으면 사용한 대체 근거와 확인 한계를 밝히고 주장 범위를 제한한다. 자료 간 충돌을 숨기거나 확인하지 않은 출처를 확인한 것처럼 연결하지 않는다.
- 공식 자료의 개념 관계·사용 계약과 사용자 자료를 대조해 학습 목적에 필요한 선행 개념·핵심 구성·구현 의무·사용 조건·대표 실패 사례가 빠졌는지 확인한다. 보완 범위는 현재 주제를 이해하고 사용하는 데 필요한 수준으로 정한다. 관련 항목을 전부 나열하거나 광범위한 학습 계획으로 확장하지 않는다.

### 설명과 개념 분리

- 한 문서는 개념 하나 또는 명확한 목적 하나를 다룬다. 같은 개념이 있으면 보완하고 중복을 만들지 않는다.
- 첫 부분에서 정의·목적·핵심 결론을 짧게 설명한다. 원리 → 필요한 예제·주의 사항 → 근거·관련 문서 순으로 자연스럽게 읽히게 한다.
- 개념 노트는 처음 읽는 사람이 이 문서와 명시된 선행 노트만으로 무엇인지·왜 필요한지·주요 구성 요소가 어떻게 동작하는지 설명할 수 있어야 한다. 용어 나열·주의 사항·외부 링크만으로 개념 설명을 대신하지 않는다. 약어와 새 전문 용어는 처음 나올 때 풀고, 필요한 전제는 짧게 설명하거나 실제 선행 노트로 연결한다.
- 요약은 본문의 입구다. 요약의 문장 수나 파일 길이를 맞추려고 필요한 원리·조건·인과 관계를 생략하지 않는다. 이해에 도움이 되는 최소 예제에는 입력·상황 → 처리 과정 → 결과·해석을 함께 적는다. 예제의 전제와 생략 범위를 밝혀 코드를 따라 쓰는 것과 원리를 이해하는 것을 연결한다.
- 분리 기준은 글자 수가 아니라 독립적인 학습 목적과 재사용 여부다. 개념·비교·실습은 목적이 다르고 독립적으로 읽을 가치가 있을 때 나누고, 짧은 설명을 읽으려 여러 문서를 왕복해야 하면 같은 문서의 절로 유지한다. index가 이미 읽기 순서·관계를 안내하면 같은 역할의 지도 문서를 추가하지 않는다.
- 기존 내용 보완은 본문 전체를 읽고 빠진 설명·모호한 주장·중복과 예제 연결을 확인한다. 정의 한 줄을 일괄 삽입하거나 제목을 바꾼 것만으로 내용 검토를 완료했다고 하지 않는다. 충분한 내용은 보존하고 부족한 부분만 보완한다.
- 양식의 모든 절을 채우기 위해 분량을 늘리지 않는다. 빈 절·안내 주석·자리표시자를 제거한다. 짧은 노트는 불필요한 목차도 생략할 수 있다. 자동 생성용 관리 주석은 보존한다.
- 위 생략·재구성은 주제별 본문에 적용한다. 필수 공통 형식(`notepilot guide format`)은 내용이 짧거나 다른 에이전트가 작성했다는 이유로 생략하지 않는다.
- 기존 노트의 유효한 설명·예제·로그·출처·이미지를 보존한다. 양식과 소제목이 다르다는 이유로 좋은 구조를 기계적으로 대체하지 않는다.
- 비교는 표, 순서는 번호 목록을 사용한다. 중복 요약·과도한 강조·깊은 목록을 줄이고 제목·목록·코드 블록 앞뒤를 빈 줄로 구분한다.
- 제목만 있는 학습 문서는 기본 개념으로 채운다. 현재 학습을 이해하는 데 필요한 전제·조건·실패 사례만 보충한다. 관련 있다는 이유로 광범위한 새 학습 계획을 만들지 않는다.
- 기존 설명의 오류 수정은 위 변경안 절차를 따른다. 모호한 표현·무조건적인 단정은 적용 조건과 보장 범위로 구체화한다.
- 실제 근거를 주장 가까이와 참고 자료에 연결한다. 외부 자료를 길게 복사하지 않는다. 출처·관찰·실행 로그·테스트 통과를 만들어 내지 않는다.
- 코드 블록에는 언어를 지정한다. 완전한 코드와 생략한 설명용 코드를 구분하고 환경·필수 설정·생략 범위를 밝힌다. 미실행 결과는 예상 결과로 적는다.
- 원래 학습 자료의 관찰과 새로 재구성한 예상을 구분한다. 서로 다른 환경·입력·실습 조건을 하나의 결과로 섞지 않는다.
