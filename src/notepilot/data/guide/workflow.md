# 작업 절차 안내

## 폴더의 역할

| 위치 | 역할 | git |
| --- | --- | --- |
| `notes/<분야>/` | 정식 노트. 형식 검사와 현황 집계 대상 | 추적 |
| `inbox/` | 나중에 정식 노트로 옮길 메모. 자유 형식 | 추적 |
| `temp/` | 붙여넣기·설정값·실험 등 임시 작업. 자유 형식 | **미추적** |
| `templates/` | 노트 양식. 사용자가 고칠 수 있음 | 추적 |
| `.notepilot/` | 도구 소유의 공통 규약·양식 원본. `notepilot upgrade`가 교체하므로 고치지 않음 | 추적 |
| `assets/` | 이미지·PDF 등 첨부 | 추적 |

API 키·토큰·비밀번호·개인 식별 정보는 추적되는 폴더에 쓰지 않는다. 꼭 적어야 하면 `temp/`에만 둔다. `notepilot check`와 커밋 전 훅이 흔한 토큰 패턴을 검사하지만 모든 비밀 값을 잡지는 못하므로 검사 통과를 안전 보증으로 보지 않는다. 이미 커밋된 비밀 값은 파일을 지워도 기록에 남으니 사용자에게 재발급을 알린다.

`temp/`는 사용자의 개인 작업 공간이다. 요청받지 않으면 읽지 않고, 그 내용을 정식 노트로 옮기지도 않는다.

## 노트 생성

1. `.notepilot/RULES.md` → 루트 AGENTS.md → 홈 문서와 분야 index → 기존 관련 노트 → 목적별 템플릿 → 근거 자료 순서로 읽는다.
2. 중복이면 기존 노트를 보완한다. 새 노트가 필요하면 AGENTS.md의 분류·명명 규칙에 맞는 분야를 정하고 `notepilot new <분야> <제목> [--type …]`로 만든다. 파일을 직접 만들지 않는다. 적합한 분야가 없으면 억지로 끼워 넣지 말고 사용자에게 새 분야를 확인한다.
3. 사용자 맥락과 일반 지식을 구분하고 핵심 설명의 근거와 중요한 누락을 대조한다. 본문·속성·날짜·related를 채우고 안내 주석과 불필요한 절을 제거한다.
4. 가장 가까운 분야 index에 연결한다. 홈 문서에는 분야 진입점 위주로 연결한다. 모든 정식 노트는 홈 문서에서 링크를 따라 도달할 수 있어야 한다. 새 분야라는 이유만으로 빈 index를 만들지 않는다.
5. `notepilot sync`로 목차·관련 문서·현황을 갱신하고 `notepilot check`로 검사한다. 사실·가독성도 직접 확인한 뒤 보고한다.

수정 순서는 **노트 → 분야 index → `notepilot sync` → `notepilot check` → 보고**다. `.notepilot/` 안의 파일은 `notepilot upgrade`가 교체하므로 고치지 않는다. 보관함별 규칙은 루트 AGENTS.md에 둔다.

위 표의 폴더 이름은 기본값이다. 이름을 바꾸려면 `notepilot rename <notes|inbox|temp|templates|assets> <새 이름>`을 쓴다. 폴더를 옮기고 링크, related, `notepilot.json`, `.gitignore`, Obsidian 설정을 함께 고친다. 사용자가 이미 직접 이름을 바꿨다면 같은 명령에 `--moved`를 붙여 나머지만 맞춘다. 본문에 글자로 적힌 옛 이름은 자동으로 고치지 않고 목록만 알려 주므로 직접 확인한다.

## 수정·이동·통합

원문과 사용자 변경 사항, 들어오는 링크를 먼저 확인한다. 유효한 내용과 근거를 보존하며 변경 목적에 맞춰 본문·날짜·검증 상태를 갱신한다. 이동·이름 변경·통합 시 문서·이미지 경로·related·목차를 함께 고친다. 도구가 이동 목적지를 추측한다고 가정하지 않는다. 통합 후 고유 내용이 남았는지 확인하고 검사한다.

## 보관·삭제

가치가 남아 있으면 archived를 고려한다. 미검증·복습 상태 때문에 자동 보관하지 않는다. 사용자가 요청했거나 승인한 범위의 중복·대체 파일만 삭제한다. 고유 내용·원본·첨부를 임의 삭제하지 않는다. 먼저 참조·내용을 확인하고 필요한 자료를 보존한 뒤 대체 연결·현황·링크를 검사한다.

## inbox 편입

`inbox/` 메모를 정식 노트로 만들 때는 중복 검색 → 근거 확인 → 템플릿과 속성 적용 → 분야 폴더 배치 → index 연결 → 검사 순서를 따른다. 원문 메모는 임의로 지우지 않으며, 삭제는 사용자가 승인한 범위에서만 한다.

## 내용 점검

`notepilot report`는 실패하지 않는 후보 목록을 낸다: 오래된 draft, needs-review, 오래된 unverified, 들어오는 링크가 없는 노트, 링크 없이 언급만 된 노트, 오래 머문 inbox 메모. 도구는 후보만 찾는다. 점검을 요청받으면 이 목록을 출발점으로 해당 노트를 직접 읽고 다음을 확인한다.

- 노트 사이에 서로 모순되는 설명이 있는가
- 더 새로운 자료나 버전 때문에 낡은 주장이 있는가
- 여러 노트에서 언급되지만 독립 노트가 없는 중요한 개념이 있는가
- 빠진 교차 참조가 있는가

발견한 내용은 먼저 보고하고, 기존 설명을 고칠 때는 `notepilot guide writing`의 변경안 절차를 따른다.

## 완료 조건

필수 속성·날짜·단일 H1·중복·자리표시자·코드 펜스·관리 영역·파일/절/첨부 링크·related와 진입 문서에서의 도달 여부를 검사한다. 갱신 후 재실행해 불필요한 변경이 없는지 확인한다.

도구 통과는 사실 검증·예제 실행·화면 표시 확인을 뜻하지 않는다. 실행하지 않은 작업을 통과했다고 보고하지 않는다. 최종 보고에는 변경한 문서·핵심 보정·실제 검증·남은 제한을 간단히 적는다.

내용 검토에서는 정의·필요성·동작·예제·조건이 해당 노트의 목적에 충분한지 직접 읽고, `notepilot guide writing`의 근거 기준에 따라 핵심 설명과 중요한 누락을 대조한다. 기존 내용의 오류 수정이 승인된 변경안과 일치하는지도 확인한다. 필수 절 이름이나 글자 수로 충실도를 판정하지 않는다. index는 경로·관계, reference는 찾는 방법·적용 범위, comparison은 비교 전제·선택 이유, lab은 실행 조건·절차·결과 해석을 각각 확인한다. 문서 전체를 대조하지 않았다면 일부 근거 확인을 전체 검증으로 표시하지 않는다.

필수 공통 형식과 내용 충실도는 별도로 확인한다. 검사 오류가 남으면 생성 완료로 보고하지 않는다. 같은 규약은 같은 형식·검사 기준을 제공하지만 서로 다른 모델의 문장·분리 판단이나 사실 정확성을 자동으로 보증하지는 않는다.
